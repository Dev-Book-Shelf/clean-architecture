# 30장 데이터베이스는 세부사항이다

데이터베이스는 데이터에 접근할 방법을 제공하는 유틸리티  
아키텍처 관점에서 저수준의 세부사항일 뿐이라 아키텍처와는 관련이 없다.

## 관계형 데이터베이스

데이터를 테이블에 행 단위로 배치한다는 자첸느 아키텍처적으로 볼 때 전혀 중요하지 않다.  
애플리케이션의 유스케이스는 이러한 방식을 알아서는 안되며 관여해서도 안된다.

## 데이터베이스 시스템은 왜 이렇게 널리 사용되는가?

지난 반세기 동안 '디스크'가 핵심 데이터 저장소였는데, 디스크의 시간 지연 때문에 색인, 캐시, 쿼리 계획 최적화가 필요해졌다.  
또한 데이터를 표현하는 표준 방식, 데이터 접근 및 관리 시스템이 요구되어 파일 시스템과 RDBMS가 만들어졌다.

## 디스크가 없다면 어떻게 될까?

한때는 디스크가 성행했지만, 이제는 소멸 중인 부품이다. 테이프, 플로피 디스크, CD가 지나온 길을 따를 것이다.  
디스크가 없다면, 모든 데이터가 RAM에 저장된다면 데이터를 어떻게 체계화할 것인가?

이 데이터들을 리스트, 트리, 스택 같은 자료 구조로 체계화 할 것이며, 우리는 이미 그렇게 일하고 있다.

## 세부사항

데이터베이스가 세부사항이라고 말하는 이유가 바로 이것 때문이다.  
데이터베이스는 그저 메커니즘이며, 디스크 표면과 RAM 사이에서 데이터를 이리저리 옮길 때 사용할 뿐이다.

아키텍처 관점에서 데이터가 어떤 형태인지는 절대로 신경 써서는 안 된다.  
우리는 디스크 자체가 존재한다는 사실조차도 인식해서는 안 된다.

## 하지만 성능은?

성능은 아키텍처와 관련된 관심사가 아닌가?  
당연히 중요하지만, 데이터 저장소의 측면에서 성능은 업무 규칙과는 분리할 수 있는 관심사다.

성능은 시스템의 전반적인 아키텍처와는 아무런 관련이 없다.

## 결론

체계화된 데이터 구조와 데이터 모델은 아키텍처적으로 중요하다.  
반면, 그저 데이터를 회전식 자기 디스크 표면에서 이리저리 옮길 뿐인 기술과 시스템은 아키텍처적으로 중요치 않다.

데이터베이스는 세부사항이다.
